# 04: Multi-token catalog search, filter chips, and SI / EE-infix engineering unit equivalence

**What to build:** End-to-end workbench search, engineering unit normalization, relevance ranking, and facet filtering. Typing a query into the top command bar's search omnibox filters the catalog in real time using multi-token `AND` matching across all 10 **Part** fields (`name`, `lcscCode`, `mpn`, `manufacturer`, `category`, `package`, resolved `Container.name`, `slot`, `notes`, and `specs` keys and values). Search normalizes Unicode electrical symbols (`µ`/`μ` → `u`, `Ω`/`ohm`/`ohms` → `r`, stripping `±`) and equates equivalent SI and EE-infix engineering values (`4k7` ↔ `4.7kΩ` ↔ `4700R`, `0.1uF` ↔ `100nF` ↔ `100000pF`, `3v3` ↔ `3.3V`, `4r7` ↔ `4.7Ω`, `2n2` ↔ `2.2nF`) across **Part** `name` and `specs` values without expanding bare 3-digit EIA numbers (`104`). Users can also slice the catalog using single-select `ChoiceChip`s (`All`, `Low Stock`, `Unassigned`, and dynamic `category` chips) that intersect via `AND` with the active search query.

**Blocked by:** 02: Physical storage hierarchy (Container management, 1-to-1 Slot uniqueness, and By Container grouped view)

**Status:** completed

- [x] Multi-token whitespace queries use `AND` semantics where every token must match at least one of the 10 searchable fields on a **Part** (`name`, `lcscCode`, `mpn`, `manufacturer`, `category`, `package`, resolved `Container.name`, `slot`, `notes`, and `specs` keys and values).
- [x] Text matching is case-insensitive and folds Unicode electrical symbols (`µ` and `μ` → `u`, `Ω`, `ω`, `ohm`, and `ohms` → `r`, stripping `±`), so queries like `"10uF"` or `"100r"` match **Parts** stored with `"10µF"` or `"100Ω"`.
- [x] Tokens with explicit SI prefixes (`p`, `n`, `u`, `m`, `k`, `M`, `G`), unit suffixes (`R`/`Ω`, `F`, `H`, `V`, `A`, `W`, `Hz`), or EE-infix notation (`4k7`, `4r7`, `100r`, `3v3`, `2n2`) are parsed into canonical `(Dimension, baseValue)` pairs (compared within $10^{-6}$ relative tolerance) so equivalent values match across `name` and `specs` values (e.g., `"4k7"` matches `"4.7kΩ"` and `"4700R"`; `"0.1uF"` matches `"100nF"` and `"100000pF"`).
- [x] Bare 3-digit integers like `"104"` are not expanded into capacitance or resistance values (avoiding false positives against quantities, **Slots**, and `Cxxxxxx` codes), while still matching MPN substrings like `"CL10B104KB8NNNC"`.
- [x] When a search query is active, matching **Parts** are ranked by best match tier—(1) exact or prefix match on `lcscCode` or `mpn`, (2) match or canonical engineering value equivalence in `name` or `specs`, (3) match in remaining fields (`slot`, `Container.name`, `package`, `category`, `manufacturer`, `notes`)—with alphabetical tie-breaking by `name`. When the search query is empty, flat view sorts alphabetically by `name`.
- [x] The single-row horizontal chip strip provides single-select `ChoiceChip`s for `All`, `Low Stock`, `Unassigned`, and each distinct non-empty `category` present in the catalog, intersecting via `AND` with the active search query.
- [x] In **`By Container`** mode, **Containers** with zero matching **Parts** are hidden whenever a search query or non-`All` filter chip is active, and shown when `All` is selected with an empty search query.
- [x] Automated tests cover SI and EE-infix value equivalence, non-expansion of bare 3-digit numbers, Unicode folding, 10-field multi-token `AND` search, 3-tier ranking, filter chip intersection, and empty-container hiding in **`By Container`** mode.
